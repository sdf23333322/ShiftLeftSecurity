01 · Introducción

¿Por qué seguridad desde el inicio?

La seguridad informática es uno de los aspectos más importantes durante el desarrollo de software. Tradicionalmente, las pruebas de seguridad se realizaban al final del proyecto, lo que generaba mayores costos y retrasos al encontrar vulnerabilidades. Para solucionar este problema surge el enfoque Shift Left Security, que propone integrar la seguridad desde las primeras etapas del desarrollo, permitiendo detectar y corregir errores antes de que lleguen a producción.

02 · Definición & principios

¿Qué es Shift Left Security?

📘 Kilonzi & Kilonzi, 2026

La seguridad Shift Left es un enfoque de desarrollo de software que busca incorporar las actividades de seguridad desde las primeras etapas del ciclo de vida del desarrollo (SDLC). Su objetivo es detectar vulnerabilidades, errores de configuración y otros riesgos antes de que el software llegue a producción, permitiendo corregirlos con menor costo, esfuerzo y tiempo. Además, fomenta la colaboración entre los equipos de desarrollo y seguridad para que la protección de las aplicaciones sea una responsabilidad compartida durante todo el proceso.

🔒 Illumio, 2025

La seguridad Shift Left es una estrategia proactiva que integra controles y prácticas de seguridad desde las fases iniciales de diseño y programación, en lugar de esperar a las etapas de prueba o implementación. Este enfoque permite identificar y solucionar problemas de seguridad de manera temprana, reducir riesgos y agilizar la entrega de software, convirtiendo la seguridad en una parte natural del trabajo diario de los desarrolladores y de las prácticas DevSecOps.

5 Principios clave de Shift Left Security
1
Automatización de pruebas de seguridad en CI/CD

Ejecutar pruebas de seguridad automáticas cada vez que se realizan cambios en el código, detectando problemas sin esperar pruebas finales.

2
Escaneo de código estático (SAST) desde la etapa de desarrollo

Análisis del código fuente mientras se programa para encontrar vulnerabilidades antes de ejecutar la aplicación.

3
Integración de análisis de dependencias para evitar vulnerabilidades conocidas

Revisar librerías y componentes externos para identificar versiones con fallos de seguridad conocidos.

4
Uso de controles de acceso y gestión de secretos en pipelines

Proteger credenciales, contraseñas y datos sensibles durante el proceso de desarrollo y despliegue.

5
Auditoría y monitoreo continuo de la infraestructura

Supervisar constantemente sistemas y recursos para detectar actividades sospechosas o posibles amenazas.

Este enfoque según Ｔｎξｃｏｍ (2025) reduce costos y tiempos de remediación, ya que corregir una vulnerabilidad en producción es mucho más costoso que hacerlo en la fase de desarrollo.

03 · Beneficios estratégicos

Beneficios de adoptar Shift Left Security

Adoptar una estrategia de desplazamiento a la izquierda aporta varios beneficios significativos a la postura de seguridad del software de una organización, según Check Point Software (2024):

Eficiencia de costos

Detectar vulnerabilidades desde el principio reduce costos de remediación. La identificación temprana evita acciones costosas tras la implementación.

Ciclos de lanzamiento más rápidos

Mantener el ritmo de Agile, DevOps y DevSecOps, abordando la seguridad concurrentemente con otras tareas.

Colaboración mejorada

Integración entre desarrollo, QA y seguridad para abordar problemas de forma eficaz desde el inicio.

Cumplimiento mejorado

Demostrar cumplimiento con normativas como RGPD o HIPAA, evitando multas y daños reputacionales.

// Sin validaciones de seguridad — lectura de archivos del servidor
String archivo = request.getParameter("archivo");
File file = new File("/docs/" + archivo);  // PATH TRAVERSAL: el usuario controla la ruta
BufferedReader br = new BufferedReader(new FileReader(file));
String line;
while((line = br.readLine()) != null){
    out.println(line);  // Sin escapar HTML → XSS potencial
}
// Sin try-catch → el servidor puede mostrar rutas internas al fallar
// Sin verificar si el usuario tiene permiso de leer ese archivo

Propuesta de Código Seguro (Mejorado)
✓ Código Seguro — Shift Left aplicado
// CÓDIGO MEJORADO — Shift Left Security aplicado — Grupo 9
import org.apache.commons.text.StringEscapeUtils;
import java.nio.file.*;

// 1. Verificar que el usuario esté autenticado
if (!isAuthenticated(request)) {
    response.sendError(HttpServletResponse.SC_UNAUTHORIZED); return;
}

// 2. Recibir y validar el parámetro con lista blanca (solo letras, números, guiones y puntos)
String archivoParam = request.getParameter("archivo");
if (archivoParam == null || !archivoParam.matches("[a-zA-Z0-9_\\-\\.]{1,100}")) {
    response.sendError(HttpServletResponse.SC_BAD_REQUEST); return;
}

// 3. Verificar que la ruta resultante esté dentro de /docs/
Path baseDir = Paths.get("/docs/").toRealPath();
Path filePath = baseDir.resolve(archivoParam).normalize();
if (!filePath.startsWith(baseDir)) {
    response.sendError(HttpServletResponse.SC_FORBIDDEN); return;
}

// 4. Leer el archivo con manejo de errores y escapar el output
try (BufferedReader br = Files.newBufferedReader(filePath)) {
    String line;
    while((line = br.readLine()) != null){
        out.println(StringEscapeUtils.escapeHtml4(line)); // Anti-XSS
    }
} catch (IOException e) {
    logger.error("Error leyendo archivo: {}", filePath, e);
    response.sendError(HttpServletResponse.SC_INTERNAL_SERVER_ERROR);
}
Mejoras aplicadas y su Principio Shift Left
🔐
Autenticación primero

Se verifica que el usuario esté logueado antes de hacer cualquier cosa. Principio: Secure by Default.

✅
Validación con lista blanca

Solo se aceptan nombres de archivo con caracteres seguros. Detectado con SAST desde el desarrollo.

🛡️
Prevención de Path Traversal

Se comprueba que la ruta final esté dentro de /docs/ usando getCanonicalPath().

🔏
Escape de salida (anti-XSS)

escapeHtml4() convierte caracteres peligrosos antes de mostrarlos al usuario.

📝
Registro de errores (logging)

Los errores se guardan en el log del servidor, no se muestran al usuario.

⚠️
Manejo seguro de excepciones

El try-catch evita que información interna del sistema quede expuesta.

06 · Reflexión crítica

Reflexiones del equipo

"La seguridad debe formar parte del desarrollo desde el inicio para evitar problemas futuros."
Reflexión 1 — Stalin Mendieta

Durante esta actividad comprendí que muchas vulnerabilidades pueden aparecer por errores simples, como no validar los datos que ingresa el usuario. Shift Left Security ayuda a identificar estos problemas desde las primeras etapas del desarrollo, lo que permite ahorrar tiempo y evitar riesgos cuando la aplicación ya está en funcionamiento.

Reflexión 2 — Leonardo Zambrano

Este tema me permitió entender que la seguridad no debe verse como una tarea final, sino como una responsabilidad presente en cada sprint. Aplicar buenas prácticas desde el inicio contribuye a crear aplicaciones más seguras, confiables y preparadas para enfrentar posibles amenazas.
